# 地图功能重新设计规范
## Map Functionality Redesign Specification

### 项目背景 / Project Background

CityZen是一个环境健康助手应用，当前的地图功能存在以下核心问题：
1. **图例位置问题**：图例反复压盖地图内容，影响用户体验
2. **路线不现实**：安全路线只是任意连接的线条，不符合真实道路网络和行人行走路径
3. **功能价值不明确**：从"环境暴露助手"角度看，当前地图功能缺乏实际指导意义

### 用户故事 / User Stories

#### 主要用户故事
**作为一个关心环境健康的用户，我希望地图能够：**

1. **US-1: 环境监测点查看**
   - 我可以查看附近的空气质量监测点
   - 我可以看到实时的环境数据（PM2.5, NO2, O3等）
   - 我可以了解不同区域的环境质量差异

2. **US-2: 环境健康区域评估**
   - 我可以看到基于环境数据的健康区域划分
   - 我可以了解每个区域的环境健康评分和建议
   - 我可以根据当前环境条件获得活动建议

3. **US-3: 时间敏感的环境指导**
   - 我可以看到基于当前时间的环境建议
   - 我可以了解一天中不同时段的环境质量变化
   - 我可以获得最佳户外活动时间建议

4. **US-4: 清晰的信息展示**
   - 图例和信息面板不会遮挡重要的地图内容
   - 我可以轻松理解地图上显示的环境信息
   - 界面简洁明了，不会造成信息过载

#### 次要用户故事
5. **US-5: 个性化环境提醒**
   - 我可以设置对特定污染物的敏感度
   - 我可以获得基于个人健康状况的环境建议

### 功能需求 / Functional Requirements

#### 核心功能 (Core Features)

**F-1: 环境监测点显示**
- 显示米兰地区的环境监测点位置
- 展示实时环境数据（基于Open-Meteo或类似可靠数据源）
- 支持点击查看详细环境数据

**F-2: 环境健康区域**
- 基于环境数据划分健康区域（优秀/良好/一般/较差）
- 每个区域显示健康评分和颜色编码
- 提供区域特定的活动建议

**F-3: 时间相关建议**
- 根据当前时间提供环境健康建议
- 显示一天中环境质量的变化趋势
- 推荐最佳户外活动时间段

**F-4: 改进的UI布局**
- 重新设计图例位置，避免遮挡地图内容
- 优化信息面板的显示方式
- 确保所有UI元素都有合适的位置

#### 移除的功能 (Features to Remove)

**R-1: 不现实的路线系统**
- 移除当前的"安全路线"功能
- 移除任意连接的线条路径
- 不再尝试提供导航功能

**R-2: 复杂的交互元素**
- 简化地图交互，专注于信息展示
- 移除过于复杂的底部面板

### 技术需求 / Technical Requirements

#### 数据源要求
**T-1: 可靠的环境数据**
- 使用Open-Meteo API获取环境数据
- 确保数据源稳定可靠
- 实现适当的错误处理和降级方案

**T-2: 本地化数据**
- 专注于米兰地区的环境数据
- 使用真实的地理坐标和区域划分
- 避免使用模拟或虚假数据

#### 性能要求
**T-3: 响应性能**
- 地图加载时间 < 3秒
- 数据更新响应时间 < 2秒
- 流畅的地图交互体验

#### UI/UX要求
**T-4: 界面设计**
- 图例位置固定且不遮挡重要内容
- 信息层次清晰，避免信息过载
- 支持响应式设计

### 验收标准 / Acceptance Criteria

#### AC-1: 环境监测点功能
- [ ] 地图上显示至少5个米兰地区的环境监测点
- [ ] 点击监测点显示当前环境数据（PM2.5, NO2, O3）
- [ ] 数据更新频率不超过1小时
- [ ] 监测点图标清晰可见，不与其他元素重叠

#### AC-2: 环境健康区域
- [ ] 地图显示至少4个不同健康等级的区域
- [ ] 每个区域有明确的颜色编码（绿色=优秀，黄色=良好，橙色=一般，红色=较差）
- [ ] 点击区域显示健康评分和具体建议
- [ ] 区域边界清晰，不会造成视觉混乱

#### AC-3: 时间相关建议
- [ ] 根据当前时间（早晨/下午/晚上）显示不同建议
- [ ] 建议内容与环境数据相关联
- [ ] 建议面板位置合适，不遮挡地图主要内容

#### AC-4: UI布局改进
- [ ] 图例位置固定在合适位置（建议左上角或右上角）
- [ ] 图例不遮挡任何重要的地图内容
- [ ] 所有文字清晰可读，字体大小适中
- [ ] 颜色对比度符合可访问性标准

#### AC-5: 功能移除验证
- [ ] 不再显示任意连接的路线
- [ ] 移除了不现实的导航功能
- [ ] 界面更加简洁，专注于环境信息展示

### 设计约束 / Design Constraints

#### DC-1: 技术约束
- 必须使用Flutter和现有的地图库
- 必须与现有的应用架构兼容
- 数据源必须免费且可靠

#### DC-2: 用户体验约束
- 界面必须保持简洁，避免信息过载
- 所有交互必须直观易懂
- 支持英文界面（课程要求）

#### DC-3: 数据约束
- 专注于米兰地区（45°28'51.3"N 9°13'30.4"E）
- 使用真实环境数据，不使用模拟数据
- 数据更新频率适中，避免过度请求

### 实施计划 / Implementation Plan

#### 阶段1: 数据层重构
1. 重新设计环境数据服务
2. 集成可靠的环境数据API
3. 实现数据缓存和错误处理

#### 阶段2: UI层重构
1. 移除现有的路线功能
2. 重新设计图例和信息面板布局
3. 优化地图交互体验

#### 阶段3: 功能集成
1. 集成环境监测点显示
2. 实现时间相关建议系统
3. 完善环境健康区域功能

#### 阶段4: 测试和优化
1. 用户体验测试
2. 性能优化
3. 错误处理完善

### 风险评估 / Risk Assessment

#### 高风险
- **数据源稳定性**：环境数据API可能不稳定或有使用限制
- **缓解措施**：实现多个数据源备份，本地数据缓存

#### 中风险
- **UI布局复杂性**：在有限的屏幕空间内合理布局所有元素
- **缓解措施**：采用渐进式设计，优先显示最重要的信息

#### 低风险
- **性能问题**：地图渲染和数据更新可能影响性能
- **缓解措施**：实现适当的数据缓存和懒加载

   - 用户界面清晰度评分：>4/5

2. **功能完整性指标**
   - 环境监测点数据准确性：>95%
   - 健康区域建议相关性：>90%

3. **技术性能指标**
   - 地图加载时间：<3秒
   - 数据更新成功率：>98%
